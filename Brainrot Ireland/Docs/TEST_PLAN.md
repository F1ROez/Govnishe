# Проверка Windows-альфы Brainrot Ireland

Дата подготовки:16 ноября2026. Этот файл — протокол и инструменты проверки, **не отчёт об успешном прохождении**. В облачной среде Unity Editor не найден; компиляция Unity/HLSL, PlayMode, Windows player,30-минутная сессия и измерения FPS/памяти здесь не запускались. Отмечать PASS можно только после проверки соответствующего сценария на готовой сборке.

## Автоматическая проверка на компьютере с Unity

Сначала закрыть Unity для этого проекта и сохранить ручные сцены. Генератор владеет MainMenu/BrainrotIreland и обновит их; запускать из отдельной рабочей копии, если есть несохранённые ручные изменения. Нужны Unity6000.3.11f1, установленный Windows Build Support, Python3.10+; для статической проверки — tree-sitter и tree-sitter-c-sharp.

```powershell
python Tools/validate_source.py
python Tools/run_alpha_checks.py --unity "C:\Program Files\Unity\Hub\Editor\6000.3.11f1\Editor\Unity.exe"
```

Вместо `--unity` можно задать переменную `UNITY_EDITOR`. Скрипт запускает последовательно реальный Unity Validate, EditMode tests, PlayMode tests и Windows build. Тесты запускаются отдельными процессами, чтобы меню/статические состояния предыдущего запуска не скрывали регрессии. Если Unity не найден, создаётся summary со статусом `blocked`, код выхода2; это **не PASS**. Нулевое число тестов, отсутствующий XML, сбой Unity, тайм-аут, отсутствие маркера Validate/артефактов дают ошибку.

Результаты: `Logs/AlphaChecks/summary.json`, XML и логи каждого этапа. Сборка: `Builds/Windows/BrainrotIreland.exe`, `alpha-build-report.json` с версией Unity, revision и SHA256 exe; готовый архив: `Builds/Packages/BrainrotIreland-Windows-alpha.zip` с кратким README управления и текстом OFL шрифта. Эти результаты не коммитятся. Для предварительного просмотра команд без запуска используйте `--dry-run`; его код0 означает только корректный разбор аргументов. `--skip-build` проверяет проект/тесты, но не создаёт player и не доказывает готовность alpha ZIP.

```powershell
python Tools/inspect_windows_zip.py Builds/Packages/BrainrotIreland-Windows-alpha.zip --metadata Builds/Windows/alpha-build-report.json --report Logs/AlphaChecks/package-check.json
```

Проверка ZIP выявляет отсутствие exe/UnityPlayer/Data, неверный хеш, повреждение архива, опасные пути, симлинки, включённые кеши проекта, DoNotShip-папки и файлы ключей подписи. Отладочные резервные папки Unity и PDB/MDB исключаются из упакованного ZIP. Статус `structure-passed` означает только целостность структуры. Исходный Unity ZIP нельзя выдавать за готовую Windows-игру.

## Измерение кадров и памяти

Для диагностики собрать отдельный Development player:

```powershell
python Tools/run_alpha_checks.py --unity "C:\Program Files\Unity\Hub\Editor\6000.3.11f1\Editor\Unity.exe" --development
Builds\Windows\BrainrotIreland.exe -brainrotDiagnostics
```

`AlphaDiagnostics` компилируется только в Editor/Development, включается только аргументом `-brainrotDiagnostics` или переменной среды `BRAINROT_ALPHA_DIAGNOSTICS=1`. В обычном Release нет этого компонента/кадрового Update. CSV `alpha-profile-<UTC>.csv` пишется в `Application.persistentDataPath`; полный путь выводится как `ALPHA_DIAGNOSTICS_CSV` в Player.log. Регистрируются раз в секунду: состояние игры, время/волна/убийства, живые/тела, наблюдавшиеся кадры, среднее/p50/p95 интервала кадров, Unity allocated bytes, managed bytes, GC0, число предупреждений/ошибок.

Это интервалы кадров по `Time.unscaledDeltaTime`, а не GPU timer или точное время главного потока. При более512кадрах/сек p50/p95 используют первые512образцов; число наблюдавшихся/взятых кадров записывается отдельно. Unity allocated/managed bytes не равны всей RAM процесса или VRAM. Запись CSV сама добавляет небольшую работу раз в секунду. Для поиска причины тормозов дополнительно использовать Unity Profiler/Memory Profiler на Development build. Финальную плавность проверить также на Release без диагностики.

Сохранить сведения об ОС/CPU/GPU/RAM, разрешении, режиме экрана, качестве, commit, настройках волн и версии Unity. Сравнивать начало/10/20/30минут именно при Playing и сопоставимой толпе. Не сравнивать меню с максимальной волной. Нужны графики/логи и численные p95/память, а не субъективное «вроде60FPS».

## Минимальный итоговый протокол

В `Logs/AlphaChecks/manual-acceptance.md` записать build/commit, устройство, даты, число реально пройденных волн, длительность, проблемы, ссылки на Player.log/CSV/видео, строки A01–A18 с фактическим статусом и список оставшихся блокеров. «Unity tests passed» не заменяет A01/A09/A16/A18. Публикация не считается выполненной этими инструментами: они создают/проверяют локальную поставку.

На Windows можно запустить `Tools/CheckAlpha.cmd` двойным щелчком: он вызывает тот же Python runner, автоматически ищущий установленный Unity Hub Editor. Python3 и Windows Build Support должны быть установлены. Закройте проект в Unity перед запуском, чтобы не получить блокировку второго Editor процесса. Наличие bat/cmd не означает выполненную сборку.

Runner использует документированный Unity 6000.3 аргумент `-buildTarget win64` (имя CLI, не C# enum StandaloneWindows64): https://docs.unity3d.com/6000.3/Documentation/Manual/EditorCommandLineArguments.html
